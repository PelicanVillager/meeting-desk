# 会议材料工作台（Meeting Desk）

**把一场会议的几十份材料拖进来，自动整理成「议程 → 议题 → 主材料 → 附件」，最后导出一个 HTML 文件放进 U 盘——开会时插到会议室电脑上，双击就能在电视上翻着看。**

全程在本机完成：文件不上传、不联网、不调用任何云端 AI 或在线 OCR。

---

## 一、先说痛点，看是不是你

在机关事业单位办会，流程大致都是这样，难受的地方也很一致：

| 会前 | 会中 | 会后 |
| --- | --- | --- |
| 各部门陆续发来一堆文件：议程、议题申报表、请示、报告、情况说明、附件、扫描件、照片 | 材料按文件名堆在一个文件夹里，轮到自己讲的时候手忙脚乱地找 | 会上记在本子上，会后要重新敲一遍 |
| 同一个议题的附件散在好几层子文件夹里，靠脑子记哪个是哪个 | 打印一堆纸，装着订书机，改一版又得重印 | 想用个工具，却担心涉密材料被传到网上 |
| 想用在线文档工具，又不敢——材料不能出本机 | 投影换一份材料就要切一次窗口 | 领导问"上个月那个事定了没"，翻半天找不到 |

**这个工具就是冲着这几件事做的。**

## 二、它能帮你做什么

### 会前：拖进去，它照着你的文件夹结构把议题摆好

把整场会议的文件夹直接拖进窗口。它是**按你原本的目录结构**理解会议的，不需要你重新命名文件：

```
20260929-党委会会议材料/
├── 党委扩大会议题第17次.docx          ← 正表：指定为「会议议程」
├── 第一议题-关于传达学习….docx        ← 指定为「第一议题」
└── 人事人才部/                        ← 部门
    ├── 2-审议关于××事项的请示/        ← 议题文件夹
    │   ├── 会议材料2-1：关于××的请示.docx
    │   └── 会议材料2-2：××情况说明.pdf
    └── 3-审议关于××申请的请示/
        ├── 会议材料3-1：关于××的请示.docx
        └── 会议材料3-2：附件材料/       ← 再深一层也能归到对应议题
```

点一下「**按目录生成议题草稿**」，它会：

- 按「部门 / 议题文件夹」自动建立议题（文件夹名开头的 `2-`、`3-` 直接变成议题顺序）
- 把议题文件夹里的材料全部挂到这个议题下
- 根目录和部门直属的文件（比如正表、打印表单）**保持不动**，等你手动指定——程序不猜

实测：一场 59 份材料、7 个议题的党委会材料，一键归入 56 份，只剩 3 份需要手动处理。

### 会中：你只需要点几下，把"谁是主材料"定下来

每个议题里的材料会排好队，你只需要点一下「**设为主材料**」，其余的自动编号成 附件1、附件2、附件3……跟纸质件的装订顺序一致。

其他地方也一样，鼠标点选就行：

- 这份是**会议议程** → 设为正表
- 这份是**议题主材料** → 填个议题名（默认取文件名）+ 部门（默认取它原来的文件夹）
- 这几份是**附件** → 选归属议题，编号留空会自动排
- 这份先放一边 → 设为**其他材料**

### 开会：导出一个文件，拷进 U 盘就走

点「**导出为单个 HTML**」，得到**一个文件**（不是一堆文件夹，不会漏拷）：

```
会议包-20260929-党委会会议材料-2026-09-29.html
```

拷进 U 盘 → 插到会议室电脑 → 双击打开 → 按 `F` 全屏投到电视。**不用装任何软件，不用联网。**

打开后是这样的：

```
┌────────────────────────┬────────────────────────────────────┐
│ ▾ 会议议程（1）         │                                    │
│ ▾ 01 第一议题（1）      │                                    │
│ ■ 人事人才部            │        当前材料（Word 按原版式、    │
│    ▾ 02 审议关于××的请示 │        PDF 按页、扫描件按图）        │
│        📄 主材料         │                                    │
│        📎 附件1          │                                    │
│        📎 附件2          │                                    │
│    ▾ 03 审议关于××的申请 │                                    │
│ ▾ 其他材料（1）         │                                    │
├────────────────────────┴────────────────────────────────────┤
│ ← 上一份   2 / 59   下一份 →     第 1 / 3 页                   │
└──────────────────────────────────────────────────────────────┘
```

用键盘就能翻完一整场会议，不用碰鼠标：

| 按键 | 作用 |
| --- | --- |
| `←` `→` | 上一份 / 下一份材料 |
| `↑` `↓` | PDF 翻页 |
| `空格` | 下一份材料 |
| `R` | **旋转**当前材料 90°（扫描件经常是倒的、横的） |
| `T` | 隐藏 / 显示左侧目录（隐藏后材料占满屏） |
| `N` | 隐藏 / 显示右侧备注 |
| `F` | 全屏 |
| `/` | 搜索材料 |

### 会中记录：随手写下，会后带走

点右侧「📝 备注」就能针对当前材料记一笔。会议结束前点「导出全部备注」，会下载一个 Markdown 文件，里面按材料分好条目，拿回来归档即可。

> 提醒：备注存在浏览器内存里，**关页面前记得导出**（页面上也有提示）。

### 会中看材料的两个小开关

- **投屏增强**：公文的仿宋、宋体笔画细，几米外看着发虚。一键换成黑体类并加粗，字号还能放大到 200%。
- **旋转**：扫描件经常方向不对（倒着的、横着的），按 `R` 转正，**每份材料各自记住角度**，翻回来还是转好的样子。

## 三、最要紧的一条：材料不出本机

这是做这个工具的前提，不是附加功能：

- 文件**只存在你自己的电脑**上，不上传、不同步、不经过任何服务器
- **不调用**云端 AI、在线 OCR、在线 PDF 解析
- 出网请求只允许本机（`127.0.0.1`）——将来接本地大模型时用；除此之外**代码里没有任何外部域名**
- 设置里有「离线自检」，还带一张**网络出站审计表**，每一次出网尝试（包括被拒绝的）都有记录，可以自己核对

材料放在这里，随时可以整个拷走备份：

```
~/Documents/会议材料工作台/
├── library/blobs/     材料原件（按内容哈希存放，同一份文件只存一份）
├── library/trash/     删掉的会议材料会移到这儿，而不是直接删除
├── meetings/          每场会议的缩略图等附属文件
├── 导出/              导出的会议包 HTML
└── db/                数据库（SQLite）
```

删会议时，材料**不硬删**，而是移到 `library/trash/`，反悔了还能捞回来；如果某份材料同时被别的会议引用，则不会动它。

## 四、怎么装怎么用

### 环境要求

- macOS 12 及以上（Apple 芯片或 Intel 都可以；本项目目前只在 Apple 芯片上实测过）
- 首次构建需要：Node.js 22+、pnpm、Rust（stable）、Xcode Command Line Tools

### 安装

```bash
git clone https://github.com/PelicanVillager/meeting-desk.git
cd meeting-desk
pnpm install
pnpm ocr-bridge     # 编译本地 OCR/渲染桥接（用系统自带能力，不下载模型）
pnpm app:build      # 打包成 .app 和 .dmg
```

把产物 `src-tauri/target/release/bundle/macos/会议材料工作台.app` 拖进「应用程序」，或在启动台里搜「会议材料工作台」。

> 从网上下载的 `.dmg` 首次打开可能被提示"无法验证开发者"，右键点图标 →「打开」即可；或者执行
> `xattr -dr com.apple.quarantine "/Applications/会议材料工作台.app"`。

### 三步上手

1. 打开应用 → 把整场会议的**文件夹**拖进窗口
2. 点「按目录生成议题草稿」→ 在每个议题里点「设为主材料」→ 把正表设为「会议议程」
3. 点「导出为单个 HTML」→ 把生成的文件拷进 U 盘 → 开会时插到会议室电脑上双击

## 五、常见问题

**材料会被上传吗？**
不会。应用只读写你本机的文件。把 Wi-Fi 关掉，导入、整理、导出、开会时阅读这一整套流程照样能用。

**支持哪些文件？**
PDF、Word（docx）、Excel（xlsx）、图片（jpg/png/webp 等）、txt。Excel 在会议包里提供下载，需要用 Office 打开。

**Word 打开会不会排版乱掉？**
会议包里用的是原版式渲染，字体、字号、表格、图片、分页都保留。公文常用的仿宋_GB2312、方正小标宋简体、黑体、楷体做了字体映射，Mac 或没装 Office 的电脑上也会找最接近的等价字体显示，不会像普通网页转换那样变成一片默认字体。

**PDF 在会议包里还是 PDF 吗？**
不是，导出时已经**逐页转成图片**了。好处是：不依赖浏览器的 PDF 组件，任何电脑、甚至电视自带浏览器都能翻页；坏处是**图片里的文字不能选中、也不能搜索**（目前搜索只覆盖材料标题）。要不要恢复成可搜索，看后面路线。

**电视上怎么放？**
会议室电脑用 HDMI 连电视，是最顺的方式：U 盘插电脑 → 双击 HTML → 按 `F` 全屏。
（如果会议室那台设备只能插 U 盘、不能插电脑，那要看它的浏览器能不能打开本地网页——绝大多数智能电视不行，这一点我没法替你保证。）

**一场会议材料太多，文件会不会很大？**
会。实测 59 份材料（含 79 页 PDF）导出后约 **36 MB**，耗时 3.9 秒。材料上百份、几百页时可能到 100 MB 以上，打开会慢一些。

**换电脑、换 U 盘还用重新整理吗？**
不用。整理结果存在本机数据库里，导出只是生成一份快照。同一份材料重复拖入也不会重复占用磁盘（按内容哈希去重）。

**能多人一起用吗？**
不能，也不打算做。这是给个人用的本地工具，没有账号、没有服务器。

## 六、现在能做什么、还不能做什么

老实交代，免得你踩坑：

**已经能用**

- 拖入文件夹/多个文件，递归扫描、跳过系统文件、按内容去重
- 按目录结构自动生成议题草稿（部门 → 议题 → 材料）
- 手动指定议程、议题主材料、附件、其他材料；附件自动编号
- 导出**单个 HTML** 会议包：目录按部门分组、议题可折叠、材料可旋转、备注可导出、全屏投屏
- 删除会议（材料进回收区，可恢复）
- 完全离线的网络守卫与出站审计

**还没做（在计划里）**

- 应用内的阅读模式（目前阅读都在导出的会议包里）
- 正文文字提取与**全文搜索**（现在只能搜标题）
- 扫描件 **OCR** 接入（底层能力已就绪，还没接进流程）
- 本地 AI 摘要、议题自动识别、附件关系自动识别（即使做，也只出"建议"，绝不自动改结构）
- 会后工作记录、待办事项
- 议题改名、排序、删除
- Windows 版本

## 七、给想改代码的人

**技术栈**：Tauri 2（Rust）+ React 19 + TypeScript + Vite，SQLite（含 FTS5 全文索引），本机 OCR 用 macOS 自带的 Vision 框架。

```bash
pnpm install          # 安装前端依赖
pnpm ocr-bridge       # 编译 Swift OCR/PDF 渲染桥接
pnpm app:dev          # 开发模式启动（热更新）
pnpm app:build        # 打包 .app / .dmg
pnpm build            # 前端类型检查 + 打包
pnpm test             # 前端单测
pnpm offline-check    # 扫描产物里有没有远程依赖（离线自检）
cd src-tauri && cargo test   # 后端单测
```

**目录结构**

```
src/                     前端（界面 + 业务服务）
src-tauri/               Rust 后端（文件、数据库、网络守卫、导出）
src-tauri/migrations/    SQL 迁移（只增不改）
src-tauri/ocr-bridge/    Swift 本机 OCR / PDF 渲染桥接
src-tauri/vendor/        随包携带的前端库（docx-preview、jszip）
docs/                    设计与开发文档
scripts/                 构建、自检、导出脚本
```

**开发约定**

1. 每完成一个模块必须自测，不通过不进下一步
2. 不私自增加云端服务；任何出网代码必须走本机白名单并写审计
3. 数据模型变更必须走迁移文件并登记到文档
4. AI 只做辅助：输出永远独立存放、带来源、需人工确认，绝不覆盖原文与人工结果
5. 文档与代码示例里**不写真实姓名和单位名**，统一用「张某」「某单位」这类代称

设计与开发过程记录在 [`docs/`](docs/)：需求分析与技术方案、会议包与 U 盘方案、开发日志。
