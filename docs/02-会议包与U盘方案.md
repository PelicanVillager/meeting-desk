# 会议包（U 盘放映）方案 v0.1

日期：2026-09-28　状态：原型已出，待现场验证

---

## 0. 一句话

把"会议材料工作台"拆成**两个产物**：

1. **工作台**（桌面应用）：会前整理材料，会中/会后归档。跑在你自己的电脑上，有数据库、OCR、AI。
2. **会议包**（可拷进 U 盘的文件夹）：会中拿到会议室去放映/阅读。**纯 HTML，双击即开，不装软件、不联网、不用数据库。**

会议包是工作台的**一次性导出物**，不是工作台本身。它的所有能力（目录、搜索、摘要）都在导出时**预先烘焙**进文件里。

## 1. 先解决一个现实问题：电视怎么显示

"U 盘插电视，电视上打开 HTML"这件事，必须先区分两种情况：

| 场景 | 可行性 | 说明 |
| --- | --- | --- |
| **A. 会议室电脑 + HDMI 到电视** | ✅ 完全可行 | U 盘插电脑，用 Chrome/Edge 双击 index.html，按 F 全屏 → 电视显示。这是绝大多数会议室的真实形态 |
| **B. U 盘直接插电视的 USB 口** | ⚠️ 基本不可行 | 智能电视（三星 Tizen / LG webOS / 安卓 TV）的文件管理器不把 `.html` 当可打开类型，也没有本地网页浏览能力；即使个别电视能打开，也没有 PDF 组件、没有稳定键盘操作 |

**结论：本方案按 A 设计。**如果要覆盖 B，需要额外做"放映包"（见第 3 节的格式 B），但即便做了，能否打开仍取决于电视本身——我不建议把方案押在这上面。

**需要确认的一件事**：会议室那台设备到底是什么？（电脑+HDMI 线 / 无线投屏盒子 / 直接插电视）这决定后面要不要做格式 B。

## 2. 硬约束：`file://` 下什么能用、什么不能用

这是整个方案的技术地基。用浏览器直接打开本地 HTML 时，浏览器出于安全会把页面当成"不透明来源"，以下限制是**确定的**：

| 能力 | file:// 下 | 后果 |
| --- | --- | --- |
| `<link>` / `<script src>`（经典脚本）/ `<img>` / `<iframe>` 相对路径 | ✅ 可用 | 所以 CSS、app.js、data.js、材料文件都能正常加载 |
| `fetch()` / `XMLHttpRequest` 读本地文件 | ❌ 被拦 | **不能用 fetch 读 data.json** → 数据必须写成 `data.js` 直接赋值给变量 |
| `<script type="module">` | ❌ 被 CORS 拦 | **不能用 ES module** → 会议包只用经典脚本 |
| Web Worker | ❌ Chrome 下被拦 | 不能把重活丢给 worker，只能同步做 |
| IndexedDB | ❌ Chrome 下不可用/不稳定 | **会中备注不能存数据库** → 存内存 + 导出文件 |
| localStorage | ✅ 可用但不保证 | 只当"锦上添花"，丢了不影响；不依赖它 |
| Blob + `<a download>` 下载 | ✅ 可用 | 会中备注靠这个导出 |
| 全屏 API | ✅ 可用 | 按 F 全屏投屏 |
| PDF 的 `#page=3` 片段参数 | ✅ Chrome 内置阅读器支持 | 页码跳转 & 翻页可以免费拿到 |
| 中文文件名 | ✅ 需 percent-encode | 导出时统一 URL 编码 |

**三条铁律**（已写进导出脚本）：
1. 不用 ES module
2. 不用 fetch/XHR 取数据（数据预烘焙进 `data.js`）
3. 不用 Worker / IndexedDB（会中数据放内存，导出靠下载）

## 3. 两种会议包格式

> **2026-09-29 更新**：软件现在自己就能导出**单个 HTML 文件**（格式 A′），
> 见第 3.3 节与 `docs/01-开发日志.md`。导出时 PDF 逐页渲染成图片内嵌，
> Word 用内嵌的 docx-preview 还原原版式，模板/脚本/数据全在一个文件里。

### 格式 A｜阅读包（推荐，保真、体积小）

```
20260929-党委会会议材料/          ← 整个文件夹拷进 U 盘
├── index.html                    ← 双击这个
├── app.css
├── app.js
├── data.js                       ← 会议结构 + 预烘焙搜索文本
├── 使用说明.txt
├── vendor/
│   ├── jszip.min.js              ← docx 解压（docx-preview 的运行时依赖）
│   └── docx-preview.min.js       ← Word 原版式渲染引擎
└── materials/                    ← 材料本体（按顺序编号）
    ├── 001-党委扩大会议题第17次⋯.docx      ← 原始文件（现场可用 WPS 打开）
    ├── 001-党委扩大会议题第17次⋯.docx.js   ← 同一份内容，base64 形式供页面渲染
    ├── 002-会议材料：关于入选⋯.docx.js
    ├── 003-会议材料1-1：关于⋯兼职情.docx.js
    ├── 004-会议材料1-2：个人兼职申请（⋯）.pdf   ← PDF 原样，iframe + #page
    └── ⋯
```

- 依赖：浏览器自带的 PDF 组件（Chrome / Edge / 国产 Chromium 内核浏览器都有）
- 体积：约等于原文件 ×2（原件 + base64 副本）。实测 11 份材料 **20MB**、12 份材料 **2.6MB**；U 盘完全无压力
- 优点：文字可选可复制、PDF 清晰、体积小

### 格式 B｜放映包（保底，兼容性最好）

- 导出时把**每一页渲染成图片**（PDF 页面、docx 排版页），拼成**单个 HTML 文件**
- 不依赖 PDF 组件、不依赖任何插件，任何浏览器都能翻页
- 代价：体积大（每页约 100–200KB）、文字不可选、不能搜索正文（只能按页索引）
- 用途：目标机器浏览器老旧、或真的要往电视 USB 口里插时，最后搏一次

**建议：默认导出格式 A；在设置里勾选"同时生成放映包"就两份都有。**

### Word 文档的显示质量（关键，已实测修好）

原型第一版用 macOS 自带的 `textutil` 转 Word，结果很糟。原因看它的输出就一目了然：

```css
p.p1 { margin: 0; text-align: center; font: 26.0px Times; color: #ff0000 }
p.p2 { margin: 0; font: 16.0px Times }
```

三个致命伤：

1. **中文字体被写成 `Times`** —— 中文只能靠浏览器兜底，字形完全不对
2. **段间距全是 0** —— 文字挤成一坨，没有公文该有的版式
3. **固定像素字号** —— 没有页面宽度概念，投到大屏上比例失调

改成 **docx-preview** 之后，它直接解析 docx 的 XML（字体、字号、颜色、表格、图片、页边距、分页），还原度接近 Word 原貌。实测渲染出的文档：

- 段落 21 个，**字号声明 39 处、字体族声明 39 处**（原先这些信息全丢了）
- 正文内容完整："某单位党委（扩大）会会议议题〔2026〕第17次会议……"

**字体问题单独处理**。实测该文档请求的字体是：

| 字体 | 出现次数 | 说明 |
| --- | --- | --- |
| 仿宋_GB2312 | 19 | 公文正文标准字体 |
| 宋体 | 14 | |
| 黑体 | 9 | |
| 方正小标宋简体 | 7 | 公文标题标准字体 |
| 楷体 | 6 | |

这些是 Windows + Office 的字体，Mac 或没装 Office 的机器上并不存在，浏览器会**悄悄换成默认字体**。会议包因此在 CSS 里加了一层别名映射，把公文常用字体名接到各平台真实存在的等价字体上（`仿宋_GB2312 → 华文仿宋`、`方正小标宋简体 → 华文中宋`、`黑体 → Heiti SC`……，Windows 上则优先命中原生字体）。

验证方式与结果（无头 Chrome 逐个 `FontFace.load()`，注意 `document.fonts.check()` 不可靠——不存在的字体名它也返回 true）：

```
仿宋_GB2312=成功  仿宋=成功  宋体=成功  黑体=成功
楷体=成功  楷体_GB2312=成功  方正小标宋简体=成功
```

另外还做了**失败兜底**：万一某份 Word 渲染不出来，页面不会白屏，而是显示错误原因 + 纯文本内容 + 一个"用 WPS 打开原件"的链接（原始 docx 就在包里）。

## 4. 阅读体验设计（投屏友好）

```
┌──────────────────────────────────────────────────────────────┐
│ 20260929-党委会会议材料  🔒本地  [搜索…]      11份  📝备注  ⛶全屏 │
├────────────────┬─────────────────────────────────────────────┤
│ 会议材料 (2)    │                                             │
│  001 党委扩大会议题第17次      │      当前材料（iframe）        │
│  011 中共中央政治局⋯           │                             │
│ 人事人才部 (9)  │                                             │
│  002 会议材料：关于入选⋯        │                             │
│  003 会议材料1-1：关于⋯兼职情   │                             │
│  004 会议材料1-2：个人兼职申请  │                             │
│  ⋯             │                                             │
├────────────────┴─────────────────────────────────────────────┤
│ ← 上一份    4 / 11    下一份 →   PDF 上一页/下一页   快捷键提示    │
└──────────────────────────────────────────────────────────────┘
```

- **字大、留白足、高对比**：站在电视几米外要能看清
- 快捷键：`←/→` 换材料，`↑/↓` 翻 PDF 页，`空格` 下一份，`F` 全屏，`/` 搜索，`Esc` 退出输入

- 按 `F` 全屏后隐藏左侧目录，画面只剩材料本身——投影时干净
- **字号按钮**：整体放大 100% → 200%（Word 与 PDF 同时生效）
- **投屏增强**：一键把正文从仿宋/宋体换成黑体类并适当加粗。公文正文笔画细，几米外看发虚，这个模式下明显更清楚

## 5. 会中记录怎么办

这是 file:// 下最受限的部分，必须设计得诚实：

| 方案 | 结论 |
| --- | --- |
| 存浏览器数据库（IndexedDB） | ❌ file:// 下不可用 |
| 存 localStorage | ⚠️ 可用但不保证，刷新/清理可能丢 |
| **导出成文件下载** | ✅ **主方案** |

具体流程：
1. 会中点右上角"📝 备注"，写针对当前材料的备注（内存中保留）
2. 会议结束前（或中途）点"导出全部备注" → 浏览器下载一个
   `20260929-党委会会议材料-会中备注.md`（含材料序号、标题、分组、备注内容）
3. 把该文件拷回工作台 → **工作台导入后自动挂到对应材料下**（M-USB4 实现）

界面上会用醒目提示写清楚："备注只存在内存里，关掉页面前务必导出"。

## 6. 搜索与 AI 摘要怎么进会议包

会议包里没有服务器、没有 OCR、没有模型，所以这两件事**在导出时就算好**：

| 能力 | 做法 |
| --- | --- |
| 全文搜索 | 导出时把每份材料已解析出的文本（PDF 文本层 / OCR 结果 / docx 正文）写进 `data.js`，页面内做内存子串匹配。命中后跳到对应材料（PDF 用 `#page=N` 定位到页） |
| AI 摘要 | 若工作台已配置本地 AI，导出时把议题摘要、关键数字、需要会议决定的事项一并烘焙进 `data.js`，会中直接展示（标注"来源：第 3 页"） |
| 未做 AI 时 | 摘要区显示"未生成"，不影响阅读与搜索 |
| 搜索不到扫描件 | 如果导出前没跑 OCR，扫描件正文搜不到——导出时给出明确警告与"先跑 OCR"按钮 |

## 7. 安全与保密：必须说清楚的一件事

**导出会议包 = 把材料复制到可移动介质，材料就离开了本机。**

这和"文件不离开本机"的原则存在真实张力，不能含糊过去。处理方式：

1. 导出前**明确提示**：本次将导出 N 份材料（列出文件名），目标位置是 U 盘，这些文件将以**明文**存在 U 盘上
2. 导出时可选**排除**若干材料（例如只带议题主材料，附件留空）
3. 会议包首页常驻显示来源（哪台机器、什么时间导出的），便于事后追溯
4. 建议 U 盘使用加密卷（macOS 加密磁盘映像 / Windows BitLocker To Go）；设置页提供指引
5. 提供"**清理 U 盘会议包**"操作，会后把备注导回工作台后即可清空
6. 会议包是**只读快照**：会中一切修改（备注）都不写回材料本身

> 一句话：导出必须是一次"有意识、有清单、可追溯"的动作，而不是顺手一拖。

## 9. 已知风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 目标机器没有 Chrome/Edge | 打不开或渲染异常 | 提供格式 B（放映包）；或会议包里附一个绿色版 Chromium 便携版（约 150MB，需另行评估合规性） |
| 浏览器策略禁止本地 PDF 显示 | PDF 只显示为下载/空白 | 格式 B；或同时在材料目录里保留 PDF 原件，可双击单独打开 |
| 电视分辨率低 / 颜色发白 | 看不清 | 大字、粗体、高对比；提供"增大字号"按钮 |
| U 盘丢失 | 材料泄露 | 加密卷 + 导出清单 + 会后清理；导出前明确提示 |
| 会中备注忘记导出 | 记录丢失 | 页面在关闭前弹确认；每 5 分钟自动尝试下载一次备份（浏览器可能拦，视为尽力而为） |
| 会议包里的材料是快照 | 与工作台后续修改不一致 | 首页显示导出时间与来源会议 ID；需要时重新导出 |
