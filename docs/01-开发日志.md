### 二、已实现的内容

**桌面壳与安全边界**

- Tauri 2 工程（`src-tauri/`），窗口标题"会议材料工作台"，1440×900，可缩放
- CSP 锁定：`connect-src` 只放行 `self` 与 `127.0.0.1 / localhost`，脚本样式只允许本地
- `capabilities/default.json` 只申请 `core:default`，**刻意不含 http / shell / process 权限**
- 关闭 updater、遥测、崩溃上报；`bundle` 未引入任何外部资源
- 网络守卫 `src-tauri/src/security/mod.rs`：出站目标必须精确等于 `127.0.0.1 / ::1 / localhost`，其余一律拒绝并写入 `net_audit` 审计表
- 所有依赖本地打包：无 CDN、无在线字体（系统字体栈）、无在线图标（内联 SVG）

**本地数据层**

- SQLite（随包编译，含 FTS5）+ WAL 模式 + 外键约束
- 迁移框架（`PRAGMA user_version`，脚本只增不改），v1 共 19 张业务表
- 内容寻址文件库：SHA-256 流式计算 + `blobs/<前2位>/<hash>.<ext>` 路径规则
- 全文检索：FTS5 **trigram** 分词器（中文子串可搜），查询短于 3 字时回退 LIKE
- 退出时 WAL 检查点，保证主库文件自身即完整数据

**本地 OCR**

- `src-tauri/ocr-bridge/main.swift`：调用系统 Vision 框架，返回文本 + 坐标 + 置信度，按阅读顺序（上→下、左→右）重排
- 协议：`meetingdesk-ocr selftest | recognize <路径> [--page N] [--lang …]`，stdout 输出单行 JSON
- Rust 侧 adapter（`src-tauri/src/ocr/`）：桥接查找、进程调用、JSON 解析、可读错误
- 支持图片与 PDF 指定页（PDF 以 2 倍分辨率渲染后识别）
- 构建脚本 `scripts/build-ocr-bridge.sh`：离线编译，不需要 Homebrew / Python / 模型下载

**应用界面（首页工作台）**

- 顶栏"会议材料工作台 + 🔒 本地模式"，右下角显示本地 AI 与 OCR 状态

- 网络出站审计表（net_audit）实时展示
- 底部常驻声明"文件仅保存在本机，不会上传云端"与库位置

**辅助脚本**

- `scripts/offline-check.mjs`：语义化扫描构建产物，拦截远程资源加载（HTML src/href、CSS url()/@import、JS fetch/WebSocket/import）

### 四、与设计文档的偏差（已在设计文档中同步）

1. **`documents` 唯一键改为 (sha256, 原始文件名)**：原来写"sha256 唯一"。改为组合键后，同一份内容以不同文件名出现时不会互相覆盖显示名；文件字节仍然只存一份（`blobs` 层去重），完全符合"不要复制文件"原则。

3. **pnpm 11 的构建脚本白名单**放在 `pnpm-workspace.yaml`（`allowBuilds`），`package.json` 里的 pnpm 字段已不被读取。
4. **退出时 WAL 检查点**：新增，原设计只提到备份快照。

### 发现

| 发现 | 数据 | 对设计的影响 |
| --- | --- | --- |
| **"附件N"命名完全没有出现** | 含"附件"字样的文件：**0 个** | 设计文档 §6.3 把"附件N"列为最高可信依据，实际场景里这条规则用不上，须下调优先级 |
| **主导命名是 `会议材料<议题号>-<序号>：<标题>`** | 7 个文件命中 `^会议材料[0-9]` | 这是"议题—材料"归属的最强信号，应作为首条规则 |
| **目录即分组** | 存在 `人事人才部/` 子目录；读书班按文件夹整体打包 | 目录名是部门/议题的高可信线索，必须在导入时保留 `folder_hint` |
| **文种词丰富** | 发言 6、函 3、议题 2、方案 2、议程 1、请示/申报表/名单/汇报 各 1 | 文种词可用于判断"主材料 vs 辅助材料" |
| **两种会议形态** | 议题式（党委会：总议题表 + 各部门议题材料）／活动式（读书班：议程 + 方案 + 发言 + 名单 + 学习资料，**没有议题层**） | 数据模型须支持"材料直接挂在会议下"，不能强制每个会议都有议题 |
| **文件名含换行符** | 有 1 个文件名中嵌入了 `\n`（网页复制粘贴的典型产物） | 导入时必须清洗显示名，且任何环节都不得因文件名异常崩溃 |
| **文件名被截断** | 存在 `…同志的兼职情.docx`（"情况"被截断） | 不能只靠文件名匹配，必须用正文兜底 |
| **待处理的杂项** | `_processed` 后缀、`.DS_Store`、文件带可执行位 | 导入时跳过隐藏/系统文件；后缀噪声要清洗 |

### 由此确定的 M1 / M2 调整

1. 导入阶段：跳过 `.DS_Store` 等隐藏与系统文件；保留 `folder_hint`；清洗**显示名**（换行→空格、压缩连续空白、去掉 `_processed` 之类后缀），但**原始文件名原样保留**
2. 识别规则优先级改为：目录分组 → `会议材料N-M` 编号 → 文种词 → "附件N" → 正文引用
3. 会议结构支持"无议题层"：材料可直接归属会议（`topic_documents.topic_id` 允许为空）
4. 附件归属除文件名外，必须有正文匹配兜底（应对文件名截断）

> 这些真实材料随后应通过应用本身导入到 `~/Documents/会议材料工作台/`，而不必留在项目目录里（项目目录只该放代码）。

## M1 + M4（部分）· 导入文件夹与角色指定（已完成，2026-09-29）

### 需求原话

> 我希望的是我能够拖入文件夹，然后选择议程文件、部门、议题主文件、议题附件

也就是：**程序不要猜，把"谁是什么"交给用户点选。**

### 已实现

**导入（Rust `src-tauri/src/organize/mod.rs`）**

- 拖入文件夹 → 递归展开；拖入多个文件 → 按份处理
- 自动跳过 `.DS_Store`、`Thumbs.db`、隐藏文件
- 计算 SHA-256 → 内容寻址落到 `library/blobs/<前两位>/<hash>.<ext>`
- **同一份内容只存一份字节**：重复导入时只建立引用关系，并回报"库里已有"
- 保留 `folder_hint`（它原来在哪个子目录，如 `人事人才部`）
- 会议名取文件夹名，并从中猜出日期（`20260929-…` → `2026-09-29`）
- 文件名清洗：控制字符（含换行）→ 空格，压缩连续空白；原始文件名原样保留

**角色指定（人工，程序不猜）**

四类角色：`agenda` 会议议程 / `main` 议题主材料 / `attachment` 议题附件 / `other` 其他材料

- 在文件行上选角色即可
- 选"议题主材料" → 填议题名称 + 部门 → **建立议题**并归入
- 选"议题附件" → 选归属议题（或新建议题）+ 可选附件编号 → **留空自动编号**（附件1、附件2…）
- 改判角色不会重复挂载：一份材料在同一会议里只有一条角色关系
- 结构与关系全部落 SQLite，随时切换会议不影响

**整理台界面**

- 左栏：待整理材料（未归类 + 其他材料），可按文件名/部门过滤，显示类型与体积
- 右栏：会议结构实时成形 —— 议程、各议题（编号、议题名、部门）、主材料、附件、未归类
- 每一项都能"移出"，回到待整理池

### 二、导出单个 HTML 会议包

**关键约束**：用户要的是**一个文件**（U 盘里就一个 html，双击打开）。而 `file://` 下浏览器
禁止 `fetch`、ES module、Worker，外部文件漏拷一个整包就废。所以模板、脚本、Word 渲染引擎、
PDF 页面、图片全部内嵌进同一个文件。

**PDF 怎么进单个文件**：导出时用系统 CoreGraphics 把 PDF 逐页渲染成 JPEG（1800px 宽、质量 0.8），
以 data URI 内嵌。这样连 PDF 阅读器都不需要，任何浏览器都能翻页——
顺带解决了电视自带浏览器可能没有 PDF 组件的问题。

**Word 怎么保持原版式**：`docx-preview` + `JSZip` 两个 UMD 脚本内嵌进文件，文档内容以 base64 内嵌，
打开时在浏览器里还原（字体、字号、表格、图片、分页）。同时带一层保险：
渲染失败就退回纯文本，并给出下载原件的入口。

**导出内容按整理好的结构组织**（这才是和普通文件夹打包的本质区别）：

```
会议议程（1）
01 审议关于对入选国家高层次人才工程项目人选进行资助的请示　·　人事人才部（2）
02 审议关于张某、李某兼职补报批的申请　·　人事人才部（7）
…
其他材料（3）
```

## 删除会议（已完成，2026-09-29）

### 行为

- 首页「最近会议」里，鼠标移到某场会议右侧会出现「删除」，点一下变成二次确认
  （「删除这场会议？（N 份材料会移到回收区，可恢复）」→ 确认删除 / 取消）
- 数据库里的会议、议题、附件关系、备注一并删除（走外键级联）
- **材料文件不硬删**，移到 `~/Documents/会议材料工作台/library/trash/<时间>-<会议名>/`，
  误删了能捞回来
- **被其他会议共用的文件不会删**：只解除本会议的关系，文件留在原处

### 为什么删掉重复会议不会立刻释放磁盘

库是按内容寻址的（同一份文件只存一份字节）。库里现有 3 场同名会议，它们**指向同一批文件**，
所以删掉前两场不会释放任何空间——只有删掉最后一场引用了这些文件的会议，文件才会进回收区。
这一点已由单测固定住：

```
删除会议时会保留仍被其他会议共用的文件
  · 两场会议导入同一批材料 → blobs 只有 4 份
  · 删第一场：documents_removed=0、blobs_moved_to_trash=0、文件原样保留、第二场材料完好
  · 删第二场：documents_removed=4、blobs_moved_to_trash=4、原目录清空、回收区出现 4 个文件
```

### 清理已执行

库中原有 2 场「未命名会议」（0 份材料，是早期测试按钮留下的），已用同一个删除逻辑清掉：

```
发现 2 场没有材料的会议
  · id=1 《未命名会议》　→ 已删除
  · id=2 《未命名会议》　→ 已删除
清理后剩余：id=3 / id=4 / id=5，各 59 份材料
```

跑法：`MD_REAL_DB="<库文件>" MD_REAL_LIBRARY="<库根目录>" cargo test 清理空会议 -- --ignored --nocapture`

### 测试

后端 30 项全部通过，其中新增 2 项：`删除会议时会保留仍被其他会议共用的文件`、`删除空会议不会出错`。

## 会议包阅读界面改进（已完成，2026-09-29）

用户反馈的四条，全部针对导出的会议包（会议室里真正在看的那一面）：

> 1. 材料内容要支持旋转，有些材料看的时候是倒着的。
> 2. 目录和备注支持隐藏功能，而且目录要按照部门的顺序来；目录和议题要支持展开和收起。

### 1. 材料旋转

- 顶栏新增「旋转」按钮，快捷键 `R`，点一次转 90°，可循环（0°→90°→180°→270°）
- **按材料分别记住角度**：翻到别的材料再回来，角度还在
- PDF 页面与图片都支持；按钮在不可旋转的材料上自动置灰
- 转 90°/270° 时先按容器宽度算最大高度再旋转，避免转完跑到屏幕外

### 2. 目录 / 备注隐藏

- 顶栏「目录」按钮（快捷键 `T`）：隐藏/显示左侧目录，隐藏后阅读区占满整个屏幕
- 顶栏「📝 备注」按钮（快捷键 `N`）：隐藏/显示右侧备注
- 两个按钮都带状态标记（`目录 ✓` / `📝 备注 ✓` 表示当前可见）

### 3. 目录按部门排序

导出时给每个议题带上它所属的部门，并按下述顺序排列：

```
分区（议程 → 部门 → 其他材料）→ 部门名 → 议题序号
```

目录里部门单独占一行，议题缩进在部门下面；只有一个部门时也会显示部门标题。

### 4. 部门与议题可折叠

- 部门标题和议题标题都变成可点：点一下收起/展开，左侧有 ▾（展开）/ ▸（收起）箭头
- **搜索时强制展开**，避免"明明匹配上了却看不见"
- 需要专注读某一节时，把其它部门/议题收起来，目录就只剩几行

### 顺手修掉的两个小问题

1. **"投屏增强"会让"字号"按钮失效**：原来用 `body.present { --doc-zoom: 1.15 }` 覆盖变量，
   而变量定义在 `body` 上会盖掉按钮设在根节点的值。改成 `calc(var(--doc-zoom) * 1.15)` 叠加。
   另外这一版才补上"目录可以隐藏"——之前 CSS 里写了 `body.focus` 规则，但没有任何按钮或按键去切换它。
2. **没有日期的会议，导出文件名不再是"…-无日期.html"**，直接就是 `会议包-第三季度读书班.html`。
